```mdx
## 3.1 Implementation Strategy

The system will be built in incremental phases, reflecting real-world enterprise delivery.

### Build Order

1. Core Transaction System

3. Analytics Layer (SQL-driven)
```

````
## 3.4 Entity Framework Core Setup

### DbContext

```csharp
public class AppDbContext : DbContext
{
    public DbSet<User> Users { get; set; }
    public DbSet<Account> Accounts { get; set; }
    public DbSet<Transaction> Transactions { get; set; }
    public DbSet<FraudFlag> FraudFlags { get; set; }

    public AppDbContext(DbContextOptions<AppDbContext> options)
        : base(options) { }
}
````

---

### Program Configuration

```csharp
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseNpgsql(builder.Configuration.GetConnectionString("DefaultConnection")));
```

## 3.5 Development Phases

---

### 3.5.1 Core Transaction System

**Goal:** Build a reliable transaction engine.

**Tasks:**

* Create models
* Run migrations
* Implement services:

  * AccountService
  * TransactionService
* Implement endpoints:

  * Deposit
  * Withdraw
  * Transfer

**Key Focus:**

* Atomic database transactions
* Balance validation
* Proper error handling

---

### 3.5.2 Fraud Detection Module

**Goal:** Add rule-based fraud detection.

**Tasks:**

* Implement FraudService
* Integrate into transaction flow
* Store fraud flags

**Integration Example:**

```csharp
await _fraudService.EvaluateTransaction(transaction);
```

## 3.6 Engineering Considerations

### Transaction Safety

* Use database transactions for transfers
* Prevent partial updates

### Separation of Concerns

* Controllers: thin
* Services: business logic
* Repositories: data access

### Extensibility

* Fraud rules should be modular
* Analytics queries should be reusable

### Error Handling

* Return proper HTTP responses
* Avoid exposing internal errors
