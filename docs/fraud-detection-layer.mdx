# Phase 4: Fraud Detection Logic

---

## 4.1 Overview

The fraud detection module is a **rule-based system** that evaluates transactions immediately after they are processed.

**Goal:**
- Identify suspicious activity
- Flag transactions for review
- Store fraud indicators for analytics

**Design Principle:**
Keep the system simple, extensible, and deterministic (no ML).

---

## 4.2 Fraud Detection Strategy

Fraud detection runs **synchronously after each transaction**.

### Flow

1. Transaction is created
2. FraudService is triggered
3. Rules are evaluated
4. If any rule is violated:
   - A FraudFlag is created
5. Result is stored in the database

---

## 4.3 Fraud Rules

---

### Rule 1: Large Transaction Threshold

**Definition:**
- Flag transactions above a defined threshold

**Example:**
- Amount > 10,000 ZAR

**Rationale:**
- Large transactions are higher risk
- Common first-line fraud check in banking systems

---

### Rule 2: High-Frequency Transactions

**Definition:**
- Flag multiple transactions within a short time window

**Example:**
- More than 3 transactions within 1 minute

**Rationale:**
- Indicates potential automated or scripted activity
- Common in fraud attempts

---

## 4.4 Fraud Service Design

### Interface

```csharp
public interface IFraudService
{
    Task EvaluateTransaction(Transaction transaction);
}
````

---

### Service Responsibilities

* Evaluate all fraud rules
* Create fraud flags
* Remain independent from transaction logic

---

## 4.5 Pseudocode Implementation

### Main Evaluation Logic

```pseudo
function EvaluateTransaction(transaction):

    if isLargeTransaction(transaction):
        createFraudFlag(transaction, "Large transaction")

    if isHighFrequency(transaction):
        createFraudFlag(transaction, "High frequency activity")
```

---

### Rule: Large Transaction

```pseudo
function isLargeTransaction(transaction):

    THRESHOLD = 10000

    return transaction.amount > THRESHOLD
```

---

### Rule: High Frequency

```pseudo
function isHighFrequency(transaction):

    TIME_WINDOW = 1 minute
    LIMIT = 3

    recentTransactions = getTransactionsForAccount(
        transaction.sourceAccountId,
        within TIME_WINDOW
    )

    return count(recentTransactions) >= LIMIT
```

---

### Creating Fraud Flag

```pseudo
function createFraudFlag(transaction, reason):

    fraudFlag = new FraudFlag
    fraudFlag.transactionId = transaction.id
    fraudFlag.reason = reason
    fraudFlag.createdAt = currentTimestamp

    save fraudFlag to database
```

---

## 4.6 Integration with Transaction Flow

Fraud detection is triggered inside the transaction service.

```csharp
await _fraudService.EvaluateTransaction(transaction);
```

**Important:**

* This happens **after the transaction is saved**
* Ensures fraud detection does not block core transaction execution

---

## 4.7 Database Considerations

To support fraud detection efficiently:

* Index transactions by:

  * AccountId
  * CreatedAt

This ensures:

* Fast lookup for recent transactions
* Efficient frequency checks

---

## 4.8 Design Trade-offs

---

### Advantages

* Simple and predictable
* Easy to implement and debug
* Fast execution (low latency)
* Transparent logic (important in banking)

---

### Limitations

* Cannot detect complex fraud patterns
* May produce false positives
* Rules require manual tuning

---

### Why This Is Still Valid

* Real banking systems often start with rule-based engines
* Machine learning is layered on top later
* Rule engines are required for compliance and explainability

---

Design the system so new rules can be added easily.
